# Spartan X (J) — дизасемблювання для ca65

[English](README.md) | **Українська**

Побайтово точне дизасемблювання **Spartan X (J) [!]** (Irem / Nintendo, Famicom; за кордоном вийшла як *Kung Fu*) для ca65/ld65,
яке можна згенерувати заново. Вихідні тексти збираються в ROM, ідентичний оригінальному дампу; усі підпрограми, змінні RAM
і більшість констант мають імена, а все дерево `src/` відновлюється з кількох файлів міток, що правляться вручну.

| | |
|---|---|
| Мапер | 0 (NROM-256), вертикальне дзеркалення |
| PRG | 32 КБ, адреси CPU $8000-$FFFF |
| CHR | 8 КБ (`gfx/`, `src/chr/`) |
| Вектори | NMI $82D8, RESET $8258, IRQ $FFF0 (вказує на дані звуку; жодне джерело IRQ не використовується) |
| Покриття | 0 невідомих байтів: близько 17,4 К коду, 14,8 К даних, 0,5 К слів-покажчиків (`docs/coverage.txt`) |

**ROM у репозиторії немає.** Покладіть власний дамп з назвою `Spartan X (J) [!].nes` у корінь проєкту (він у `.gitignore`).
Очікуваний розмір: 40976 байтів (16-байтний заголовок iNES + 32 КБ PRG + 8 КБ CHR).

## Вимоги

- [cc65](https://cc65.github.io/) (`ca65` і `ld65` у `PATH`)
- Python 3
- за бажанням: `make`; Mesen 2 у `mesen/` для скриптів безголового профілювання (у репозиторій не входить)

## Збірка і перевірка

```
python tools/disasm.py --build   # згенерувати src/ з tools/labels/*.txt, зібрати, порівняти -> IDENTICAL
python tools/lint_labels.py      # 0 problems
python tools/reloc_test.py       # 0 pointers that did not move
python tools/selftest.py         # OK
```

Інші способи зробити те саме:

| Команда | Дія |
|---|---|
| `make` / `assemble.bat` | зібрати `game.nes` з наявного `src/` |
| `make check` / `compare.bat` | зібрати й порівняти з оригіналом: `IDENTICAL` |
| `make test` | перевірка + лінтер + тест релокації + самотест |

## Редагування

`src/` **генерується**. Імена, класифікація й константи живуть у трьох файлах, що правляться вручну (формат описано
в заголовку кожного):

- `tools/labels/rom.txt`: мітки ROM, класифікація код/дані/таблиця/текст/слова, модулі, примітки
- `tools/labels/ram.txt`: змінні RAM
- `tools/labels/const.txt`: іменовані константи й підстановки операндів (`NAME = value`, `use`, `data`)

Після правок запустіть `python tools/disasm.py --build`. Якщо ви правите `src/` вручну (для хаку), запускайте генератор
лише з `--out DIR`, інакше він перезапише ваші зміни. Пропатчена збірка вже не буде `IDENTICAL`.

## Структура репозиторію

```
src/                  згенеровані тексти ca65 (src/prg/*.asm по модулях, src/chr/ банки CHR, *.inc)
tools/                генератор, лінтер, тест релокації, самотест, xref, інструмент CHR, інструменти метаспрайтів і мапи спавну
tools/labels/         rom.txt, ram.txt, const.txt: вручну редаговане джерело всіх імен
tools/mesen/          безголовий бот профілювання для Mesen 2 (profile.lua, run_profile.py)
docs/                 документація та згенеровані звіти (див. нижче)
gfx/                  аркуші таблиць шаблонів CHR (генерує tools/chr_tool.py)
config.cfg            конфігурація ld65 (заголовок iNES + 32 КБ PRG + 8 КБ CHR)
header.bin            16-байтний заголовок iNES, підключається в src/main.asm
Spartan X (J) [!].cdl журнал код/дані Mesen, який читає генератор
game.mlb              мітки для Mesen (генерується)
Makefile, *.bat       скрипти збірки
AGENTS.md, CLAUDE.md  правила роботи для ШІ-асистентів (CLAUDE.md лише підключає AGENTS.md)
```

Поза репозиторієм (у `.gitignore`): ROM і всі `*.nes`, результати збірки (`*.o`, `game.map`, `game_labels.txt`),
емулятор `mesen/`, `reference/` (збережені сторінки третіх сторін), `skills/` і `TEMPLATE.md` (матеріали шаблону
проєкту дизасемблювання), результати профілювання.
