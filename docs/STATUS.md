# Status: what is verified and what is not

- Names come from the code structure, GameHacking.org RAM codes and the Data Crystal RAM map for the US *Kung Fu* (<https://datacrystal.tcrf.net/wiki/Kung_Fu_(NES)/RAM_map>); many of that map's addresses match this version. Checked in Mesen so far: the music and DMC requests, `floorGoesRight`, `timerMode`, `difficulty`, the game modes, `lives`, `playerHealth`, `bossHealth`, `floorTime`, `scrollPage`, `playerFloor`, `floor`, `demoMode`, `gameSelect` and the PPU jobs listed above; with `--extra` probes also `objFacing`, `hardRules`, `throwerHold`, `OBJST_ALT`, the
  `objX` slots, `DrawPagePlaque`, the ending hearts, `SFXN_SWING`, `GRIPPER_POSE_GRAB_2`, the `DrawObjectState` modes (pot, dragon breath, dragon smoke) and the later-loop ending heart
  (`curDefeatCount` forced to 1).
- Not done yet:
  - no `loc_`, `sub_`, `dat_` or `tbl_` labels are left and no `(?)` marks; resolved from the code only (not seen in
    Mesen): the floor 4 flyer moves (`flyerMode`, `MoveFlyer`), `Boss4SparkDY`, `BossWaitPage`, `KnifeThrowerKeepRange`
  - every RAM address used by the code has a name except the scratch bytes $0000-$000F (`ptr_00`..`ptr_07`, `ram_000A`..`ram_000F`); the names added last (end of `ram.txt`) come from the code only, not from Mesen
  - `const.txt` names the PPU, APU and joypad bits, the game modes (`GM_*`), the warm-boot signature, the timer period, the starting lives, the floor timer (`FLOOR_TIME_*`), attack kinds (`ATTACK_*`), the OAM record (`Sprite` struct), the demo flag, the music and sound effect requests (`MUSIC_*`, `SFX1_*`, `SFX2_*`, `SFXN_*`, `DMC_*`), floors (`FLOOR_*`), object types (`OBJ_*`), `objState` bits (`OBJST_*`), positions, the player action bits (`PA_*`), object poses (`KT_POSE_*`, `GRIPPER_POSE_*`, `BOSS*_POSE_*`), object slots (`SLOT_BOSS`, `SLOT_PLAYER`, `ENEMY_SLOTS`), hit boxes, sprite attribute bits and sizes (`SPR_*`, `SPRITE_BYTES`, `TILE_PX`), effect tiles and times, HUD score positions and all song data. HUD layout (`*_PPU`, `HEALTH_*`, `SCORE_*`), `objMode` values (`OBJMODE_*`) and screen zones. About 460 immediates (other than 0, 1, $FF) are still numeric: mostly object timer durations, positions, sprite tiles, random masks and PPU buffer records in the object modules.
    Checked in Mesen (probe runs on floors 1-2, 4 and 5): the drawing order starts with `SLOT_PLAYER`; `CMP #PA_KICK-1` passes only with `PA_KICK`/`PA_PUNCH` set; `BOSS_ATTACK_LOW` = crouching poses 6-8 of the floor 1 boss and `BOSS5_ATTACK_LOW` = crouching poses $0D-$10 of the floor 5 boss; `EFFECT_TILE_*` order; `POPUP_TIME` / `POPUP_TIME_BOSS`; `KNIFE_RIGHT_BIT` with a right-facing thrower; the `OBJMODE_*` values by object type; boss healing every 141-146 frames (`BOSS_HEAL_PERIOD` slow ticks); `WALK_CARRY_TIME`, `SCROLL_ACTIVE_TIME`, `SPAWN_STEP_PX` (spawnStepFine 0-$17), `BOSS4_CAST_TIME`, `BOSS_WAIT_TIME`; the HUD positions on a screenshot. Second probe round: the extra life (forcing `score+2` = 5 gave `lives` +1 and set `extraLifeGiven`, so `EXTRA_LIFE_DIGIT` is 50000 points); the floor 4 double (`BOSS4_DOUBLE_TIME`, `BOSS4_DOUBLE_WAIT` code ran once per double, `bossWaitTimer` was 0 at the start, the double lived 382-425 frames); `DMC_SEQ_A` in `dmcSfxPlaying` (Sylvia scene, floor 2). `PLAYER_X_MIN/MAX` never matter in practice: `objX+6` stayed $80-$E3 during play. Third probe round: hit-box offsets and loop bounds (`POINT_BOX_*`, `HOP_BOX_*`, `SPARK_*`, `RNG_BYTES`, `EFFECT_SLOTS`, …) are checked by the build against the bytes; timer loads (`ACTION_LOCK_TIME`, `FLOOR_START_TIME`, `TITLE_IDLE_TIME`, `DEATH_WAIT_TIME`, `SCENE_*_TIME`, `SYLVIA_WAIT_TIME`, `ENDING_GAP_TIME`) were all seen with exactly these values. Per-object timers (`objActTimer`, `objSlowTimer`) and sound timers vary per pose or note and stay numeric. Still not seen: `BOSS_HIT_WINDOW` (the bot never hit boss 2 or 4 there). `DMC_SEQ_C` / `DMC_SEQ_D` were checked by forcing `dmcSfxQueue` = $40 / $80 in Mesen (the compares at FAA3/FAA7 start sequences $40 / $80); that the floor 3 and 4 bosses really queue them was not seen, because the bot never died to those bosses.
  - the ending (mode 6) was reached in Mesen by starting the bot on floor 5
  - two-player game (2P game A): in Mesen `currentPlayer` switches after every death, `lives` drops only for the player who died, and the game ends when both have none. Not checked: per-player score (`scoreP1`/`scoreP2`), `extraLifeGiven`, `attackLatch`, `playerFloor` and `defeatCount` of player 2 (the bot always died on floor 1)
